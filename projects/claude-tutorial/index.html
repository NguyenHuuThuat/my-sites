Tập II · tiếp nối Bách khoa Claude

Claude Code, từ A đến vận hành thật Toàn bộ kiến thức và kinh nghiệm cần thiết để dùng agent lập trình của Anthropic ở mức thành thạo — cho Data Scientist, AI engineer và web developer.

Claude Code không phải autocomplete. Nó là một môi trường agentic: đọc cả codebase, lập kế hoạch xuyên nhiều file, chạy lệnh, tự kiểm tra và lặp lại trong khi bạn quan sát, chỉnh hướng, hoặc rời đi. Cuốn này đi sâu vào cơ chế và những thói quen tạo nên khác biệt giữa "thử cho biết" và "giao việc thật".

terminal · IDE · desktop · web CLAUDE.md · skills · subagents · hooks · MCP nguồn: docs chính thức 06/2026
~/projects/payments — claude
$ cd payments && claude

● plan mode · đọc 7 file · soạn kế hoạch 5 bước → chờ bạn duyệt
>

Cách đọc: 12 mục, đi từ mô hình tư duy → cơ chế → cấu hình → tự động hoá. Mọi đoạn code đều copy chạy được. Cột trái là mục lục cố định.

01

Nền tảng

Mô hình tư duy & vòng lặp agent

Hiểu một câu này là hiểu 80% còn lại: Claude Code chạy một vòng lặp đọc → lập kế hoạch → hành động → kiểm tra → lặp lại, và mọi best practice đều xoay quanh một ràng buộc duy nhất — cửa sổ ngữ cảnh đầy nhanh, và hiệu năng giảm khi nó đầy.

Hai hệ quả phải thuộc lòng

hệ quả 1

Cho Claude cách tự kiểm tra

Claude dừng khi việc "trông có vẻ xong". Nếu không có thứ trả về pass/fail (test, build exit code, linter, screenshot so với design), bạn chính là vòng kiểm tra — mỗi lỗi phải chờ bạn phát hiện. Có "check", vòng lặp tự đóng: Claude làm → chạy check → đọc kết quả → lặp tới khi đạt.

hệ quả 2

Ngữ cảnh là tài nguyên khan hiếm

Cửa sổ ngữ cảnh chứa cả hội thoại: mỗi tin nhắn, mỗi file đã đọc, mỗi output lệnh. Một phiên debug có thể ngốn hàng chục nghìn token. Khi ngữ cảnh đầy, Claude bắt đầu "quên" chỉ dẫn cũ và mắc lỗi nhiều hơn. Quản lý ngữ cảnh là kỹ năng quan trọng nhất (xem mục 04).

Đổi cách làm việcThay vì bạn viết code rồi nhờ Claude review, bạn mô tả điều muốn và Claude tự khám phá–lập kế hoạch–hiện thực. Bạn chuyển vai từ người gõ phím sang người định hướng và duyệt kết quả. Điều này cần một đường cong học — phần còn lại của cuốn này là đường cong đó.
02

Bắt đầu

Cài đặt & các bề mặt

Một engine, nhiều nơi chạy. Cài CLI một lần, rồi dùng ở terminal, IDE, desktop, hoặc cloud tùy ngữ cảnh.

Cài đặt (khuyến nghị: native installer)

# macOS · Linux · WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# Homebrew (không tự cập nhật → brew upgrade claude-code)
brew install --cask claude-code

# Windows winget · hoặc apt/dnf/apk trên Debian/Fedora/RHEL/Alpine
winget install Anthropic.ClaudeCode

# Khởi động trong bất kỳ project nào
cd your-project && claude   # lần đầu sẽ yêu cầu đăng nhập
Lưu ý nền tảngBản native tự cập nhật nền. Trên Windows: dấu nhắc PS C:\ là PowerShell, C:\ là CMD — dùng đúng lệnh. Nên cài Git for Windows để Claude dùng được Bash tool (WSL thì không cần). Gặp lỗi cài → xem trang Troubleshoot install.

03

Quy trình lõi

Vòng lặp làm việc chuẩn: Khám phá → Lập kế hoạch → Hiện thực → Commit

Để Claude nhảy thẳng vào code dễ tạo ra code giải sai bài toán. Tách nghiên cứu/lập kế hoạch khỏi hiện thực là thói quen có giá trị nhất.

Khám phá (plan mode). Vào plan mode (Shift+Tab). Claude đọc file, trả lời câu hỏi, không sửa gì. "đọc /src/auth, hiểu cách quản session và login; xem cách quản biến môi trường cho secret."

Lập kế hoạch. Yêu cầu kế hoạch chi tiết. "tôi muốn thêm Google OAuth. file nào cần đổi? luồng session ra sao? tạo kế hoạch." Nhấn Ctrl+G để mở kế hoạch trong editor và sửa trước khi chạy.

Hiện thực. Rời plan mode, để Claude code và đối chiếu kế hoạch. "hiện thực luồng OAuth từ kế hoạch của bạn. viết test cho callback handler, chạy test suite và sửa lỗi."

Commit. "commit với message mô tả rõ và mở PR." Claude làm việc trực tiếp với git: stage, viết message, tạo branch, mở PR.

Khi nào bỏ qua planPlan mode có chi phí phụ. Việc nhỏ scope rõ (sửa typo, thêm log, đổi tên biến) → bảo Claude làm thẳng. Lập kế hoạch đáng giá khi: bạn chưa chắc hướng đi, thay đổi nhiều file, hoặc bạn lạ vùng code đó. Nếu mô tả được diff trong một câu, bỏ plan.

Cho Claude một "check" để tự đóng vòng

Đây là đòn bẩy lớn nhất để biến "phiên phải ngồi canh" thành "phiên giao xong rồi đi". Check là bất cứ thứ gì trả về tín hiệu Claude đọc được:

Mức siếtCơ chếKhi dùng
Trong 1 prompt"viết test, chạy, sửa tới khi xanh" ngay trong câu lệnhMọi việc, dùng được ngay hôm nay
Cả phiên/goal đặt điều kiện; bộ đánh giá re-check sau mỗi lượtĐể phiên không giám sát tự kết thúc đúng
Cổng cứngStop hook chạy script, chặn kết thúc lượt tới khi passBắt buộc tuyệt đối (gate xác định)
Ý kiến thứ haiSubagent kiểm chứng / model khác cố bác bỏ kết quảNgười làm không phải người tự chấm
MẹoYêu cầu Claude trưng bằng chứng thay vì khẳng định "đã xong": output test, lệnh đã chạy & kết quả, hoặc screenshot. Đọc bằng chứng nhanh hơn tự chạy lại — và áp dụng được cho cả phiên bạn không ngồi xem.

Prompt cụ thể — càng chính xác càng ít phải sửa

YếuMạnh
"thêm test cho foo.py""viết test cho foo.py, phủ ca biên người dùng đã logout. tránh mock."
"sửa bug login""user báo login fail sau khi session timeout. kiểm tra src/auth/, nhất là token refresh. viết test fail tái hiện lỗi, rồi sửa."
"thêm calendar widget""xem widget hiện có ở home page để hiểu pattern; HotDogWidget.php là ví dụ tốt. theo pattern đó, build calendar widget, không thêm thư viện ngoài cái đã có."

Cấp dữ liệu giàu: tham chiếu file bằng @file (Claude đọc trước khi trả lời), dán/kéo-thả ảnh, đưa URL tài liệu (allowlist domain hay dùng qua /permissions), hoặc pipe: cat error.log | claude.

Để Claude phỏng vấn bạn (cho tính năng lớn)

Tôi muốn xây [mô tả ngắn]. Hãy phỏng vấn tôi kỹ bằng AskUserQuestion.
Hỏi về hiện thực kỹ thuật, UI/UX, ca biên, đánh đổi. Đừng hỏi hiển nhiên,
đào vào phần khó tôi có thể chưa nghĩ tới. Hỏi tới khi đủ, rồi viết spec đầy đủ vào SPEC.md.

Khi spec xong, mở phiên mới để thực thi — context sạch, tập trung hoàn toàn vào hiện thực, lại có spec viết sẵn để đối chiếu. Spec tốt là spec tự đủ: nêu tên file/interface liên quan, ghi rõ cái gì ngoài phạm vi, và kết bằng một bước xác minh end-to-end.

04

Kỹ năng quan trọng nhất

Ngữ cảnh — quản lý quyết liệt

Phiên dài làm ngữ cảnh đầy file/lệnh/hội thoại không liên quan, làm giảm hiệu năng và đánh lạc hướng Claude. Chủ động dọn là việc bạn phải làm thường xuyên.

/clear

Reset giữa các việc

Dùng /clear thường xuyên khi chuyển sang việc không liên quan. Một phiên sạch với prompt tốt hơn gần như luôn thắng một phiên dài chất đầy sửa chữa.

/compact

Nén có chủ đích

Tự động nén khi gần đầy (giữ code & quyết định quan trọng). Chủ động: /compact Focus on the API changes. Tinh chỉnh trong CLAUDE.md: "khi nén, luôn giữ danh sách file đã sửa và lệnh test".

Esc · /rewind

Sửa hướng sớm

Esc dừng giữa chừng (giữ context để chỉnh). Esc Esc hoặc /rewind mở menu khôi phục hội thoại & code về mốc trước, hoặc tóm tắt từ một điểm chọn. "Undo that" để hoàn tác.

/btw

Hỏi vặt không tốn context

Dùng /btw cho câu hỏi nhanh không cần lưu — câu trả lời hiện ở lớp phủ, không vào lịch sử hội thoại, nên không phình ngữ cảnh.

Quy tắc kinh nghiệmNếu bạn đã sửa Claude hơn 2 lần về cùng một vấn đề trong một phiên, ngữ cảnh đã bị chất đầy các hướng đi sai. Hãy /clear và bắt đầu lại với prompt cụ thể hơn (gói cả những gì bạn vừa học). Đừng cố kéo dài.

Dùng subagent để điều tra

Giao việc đọc-nhiều-file cho subagent: "dùng subagent để điều tra X". Nó khám phá trong context riêng và chỉ trả về tóm tắt — giữ hội thoại chính sạch. Theo dõi mức dùng context liên tục bằng status line tùy biến.

05

Ngữ cảnh bền vững

CLAUDE.md & bộ nhớ

CLAUDE.md là file Claude đọc đầu mỗi phiên — nơi đặt ngữ cảnh nó không thể suy ra từ code. Chạy /init để sinh bản khởi đầu (tự dò build system, test framework, pattern), rồi tinh chỉnh dần.

# CLAUDE.md — ngắn, người-đọc-được
# Code style
- Dùng ES modules (import/export), không CommonJS (require)
- Destructure import khi có thể

# Workflow
- Typecheck sau mỗi loạt thay đổi
- Ưu tiên chạy test đơn lẻ, không chạy cả suite (cho nhanh)

# Import file khác bằng @path
See @README.md for overview and @package.json for npm commands.
- Git workflow: @docs/git-instructions.md

Skills — đơn vị linh hoạt nhất

Một skill là file markdown chứa kiến thức/workflow. Đặt trong .claude/skills/<tên>/SKILL.md. Claude tự nạp khi liên quan, hoặc bạn gọi /<tên>. Hai loại: reference (kiến thức dùng suốt phiên) và action (làm việc cụ thể).

# .claude/skills/fix-issue/SKILL.md
---
name: fix-issue
description: Sửa một GitHub issue
disable-model-invocation: true   # chỉ gọi tay (việc có side-effect)
---
Phân tích và sửa issue: $ARGUMENTS.
1. gh issue view để lấy chi tiết
2. tìm file liên quan trong codebase
3. sửa, viết & chạy test
4. đảm bảo qua lint & typecheck
5. tạo commit message mô tả, push, mở PR

Gọi: /fix-issue 1234. Dùng disable-model-invocation: true cho workflow có side-effect mà bạn muốn tự kích.

Subagents — cô lập ngữ cảnh

Subagent chạy trong context & bộ tool riêng; hữu ích cho việc đọc nhiều file hoặc cần tập trung chuyên môn mà không làm rối hội thoại chính. Đặt ở .claude/agents/<tên>.md:

# .claude/agents/security-reviewer.md
---
name: security-reviewer
description: Review code tìm lỗ hổng bảo mật
tools: Read, Grep, Glob, Bash
model: opus
---
Bạn là senior security engineer. Soát:
- Injection (SQL, XSS, command)
- Lỗi xác thực/phân quyền
- Secret/credential lộ trong code
Đưa tham chiếu dòng cụ thể + cách sửa.

Gọi rõ: "dùng subagent review code này về bảo mật." Khác với agent team (nhiều phiên độc lập nhắn nhau, tốn token hơn) — subagent rẻ hơn vì chỉ tóm tắt trả về context chính.

Hooks — xác định, không phải khuyến nghị

Khác CLAUDE.md (mang tính khuyên), hook đảm bảo hành động luôn xảy ra. Cấu hình trong .claude/settings.json; xem bằng /hooks (chỉ-đọc). Sự kiện chính: PreToolUse, PostToolUse, Notification, Stop, SessionStart, nén ngữ cảnh…

# Tự format sau mỗi lần sửa file
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
        "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }]
    }]
  }
}
# Chặn sửa file nhạy cảm — .claude/hooks/protect-files.sh
#!/bin/bash
INPUT=$(cat); FILE=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
for p in ".env" "package-lock.json" ".git/"; do
  if [[ "$FILE" == *"$p"* ]]; then
    echo "Blocked: $FILE khớp pattern bảo vệ '$p'" >&2
    exit 2          # exit 2 = chặn, Claude nhận phản hồi để đổi hướng
  fi
done
exit 0

Plugin: /plugin duyệt marketplace; cài code intelligence plugin cho ngôn ngữ có kiểu để Claude điều hướng symbol chính xác.

Kiểm soát

Quyền & an toàn

Mặc định Claude Code hỏi trước mỗi hành động có thể đổi hệ thống (ghi file, lệnh Bash, tool MCP). An toàn nhưng phiền. Permission mode điều chỉnh tần suất hỏi đó.

ModeChạy không hỏiHợp với
defaultChỉ đọcBắt đầu, việc nhạy cảm
acceptEditsĐọc + sửa file + lệnh fs phổ thông (mkdir, mv, cp…)Lặp trên code bạn đang review
planChỉ đọc (không sửa source)Khám phá codebase trước khi đổi
autoMọi thứ, có classifier an toàn nềnViệc dài, giảm mệt vì prompt
dontAskChỉ tool đã pre-approveCI & script khoá chặt
bypassPermissionsMọi thứ (bỏ qua lớp quyền)Chỉ trong container/VM cô lập

Đổi mode: Shift+Tab để xoay (default → acceptEdits → plan), hoặc cờ --permission-mode plan khi khởi động, hoặc đặt mặc định trong settings:

{ "permissions": { "defaultMode": "acceptEdits" } }

Phủ lên mode bằng permission rules: allowlist tool an toàn (npm run lint, git commit) qua /permissions, hoặc bật cô lập OS bằng /sandbox. Trong mọi mode trừ bypassPermissions, ghi vào protected paths không bao giờ tự duyệt — bảo vệ trạng thái repo và cấu hình của chính Claude.

Lưu ý về auto modeAuto mode là research preview: một model classifier soát hành động, chặn cái leo thang ngoài yêu cầu / nhắm hạ tầng lạ / bị nội dung độc điều khiển. Nó giảm hỏi nhưng không đảm bảo an toàn — dùng cho việc bạn tin hướng đi, không thay cho review ở thao tác nhạy cảm. Yêu cầu model đủ mới (Sonnet 4.6 / Opus 4.6+), Anthropic API, và admin bật (Team/Enterprise). Claude Code cố tình bỏ qua defaultMode:"auto" trong settings của project để repo không tự cấp quyền cho mình.
Nguy hiểm--dangerously-skip-permissions (bypass) bỏ toàn bộ kiểm tra — chỉ dùng trong môi trường cô lập, không có dữ liệu/khóa thật. Đừng chạy với quyền truy cập internet trên máy chứa secret.

Lập trình hoá

Headless · scripting · CI

Cùng tool, agent loop và quản lý ngữ cảnh của Claude Code — nhưng chạy không tương tác. Nền tảng cho script, CI/CD, và Agent SDK.

# -p (--print): chạy không tương tác; mọi cờ CLI đều dùng được
claude -p "tìm và sửa bug trong auth.py" --allowedTools "Read,Edit,Bash"

# --bare: bỏ auto-discovery (hooks/skills/MCP/CLAUDE.md) → kết quả nhất quán mọi máy
claude --bare -p "Tóm tắt file này" --allowedTools "Read"

# Pipe vào / chuyển ra như mọi công cụ CLI
cat build-error.txt | claude -p 'giải thích gọn nguyên nhân gốc lỗi build' > out.txt

# Output có cấu trúc + JSON Schema để parse an toàn
claude -p "trích tên các hàm trong auth.py" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
  | jq '.structured_output'
--output-format

3 dạng ra

text (mặc định) · json (kèm result, session id, metadata, total_cost_usd) · stream-json (NDJSON realtime, dùng với --verbose --include-partial-messages).

--bare

Cho CI & SDK

Bỏ qua hooks/MCP/CLAUDE.md của máy → tránh "chạy máy tôi thì khác". Chỉ cờ bạn truyền mới có tác dụng. Auth qua ANTHROPIC_API_KEY. Sẽ thành mặc định của -p tương lai.

Claude như linter trong package.json

{
  "scripts": {
    "lint:claude": "git diff main | claude -p \"bạn là typo linter. với mỗi typo trong diff, in filename:line rồi dòng sau là vấn đề. không gì khác.\""
  }
}

Để kiểm soát đầy đủ (structured output, callback duyệt tool, message object), dùng Agent SDK bản Python hoặc TypeScript. CI: GitHub Actions / GitLab CI/CD để tự review PR & triage issue; tag @claude trong PR/issue.

Thư mục .claude/Nơi Claude Code đọc cấu hình: CLAUDE.md, settings.json, hooks/, skills/, commands/, agents/, rules/, auto memory — ở cả gốc project (.claude/) lẫn home (~/.claude/). Check phần dùng chung vào git để cả team thừa hưởng.

Theo nghề

Playbook cho DS/AI engineer & Web dev

Cùng một bộ cơ chế, ghép khác nhau theo loại việc.

Data Scientist / AI engineer

onboarding

Hiểu codebase mới

Hỏi Claude như hỏi senior: "logging hoạt động ra sao?", "tạo API endpoint mới thế nào?", "dòng 134 foo.rs làm gì?". Không cần prompt đặc biệt — rút ngắn thời gian ramp-up.

pipeline ML

Cắm vào repo thật

Để Claude Code đọc repo training/eval, thêm metric (F1 theo lớp, specificity/sensitivity), viết test cho data loader, chạy & sửa. Đặt "luôn typecheck + chạy test lớp" trong CLAUDE.md.

eval & verify

Cho nó cách tự chấm

Đặt một script eval làm "check": Claude sửa model/feature → chạy eval → đọc số → lặp tới khi đạt ngưỡng. Dùng subagent kiểm chứng để model khác soát lại kết quả.

data ops

Làm sạch & sinh

Script làm sạch/chuyển định dạng, sinh dữ liệu cân bằng lớp hiếm, vẽ biểu đồ chẩn đoán — chạy headless trong pipeline (claude -p --bare) để tái lập được.

Web developer

feature

Explore→Plan→Code→Commit

Tính năng lớn: để Claude phỏng vấn → SPEC.md → phiên mới thực thi. Tham chiếu pattern sẵn có ("xem cách widget X làm") để code khớp codebase.

debug

Test fail trước, sửa sau

"viết test fail tái hiện bug, rồi sửa, address nguyên nhân gốc, đừng suppress lỗi." Dán stack trace + mô tả triệu chứng + nơi nghi ngờ.

chất lượng

Hook + CLAUDE.md

Hook auto-format/lint sau mỗi edit (xác định, không lệ thuộc LLM nhớ); checklist review trong CLAUDE.md để chuẩn hoá cả team; code intelligence plugin cho TS/typed.

UI

Screenshot làm check

"[dán screenshot] hiện thực design này, chụp lại kết quả, liệt kê khác biệt và sửa." Dùng Chrome (beta) để đọc console & so sánh trực quan.
